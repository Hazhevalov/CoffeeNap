# Загрузка страниц и навигация Android

Актуальные исправления пагинации, фоновых таймеров, календарного кеша и проверки от 23.09.2026 приведены в [отчёте аудита](audit-2026-09.md). Ниже сохранена история проверки от 08.09.2026.

## Изменения

- `MauiXamlInflator=SourceGen`: конструкторы XAML генерируются при сборке в Debug и Release. Это касается страниц, общих контролов и лениво загружаемых шагов формы. Раньше Debug использовал разбор XAML во время исполнения.
- Shell создаёт только выбранную страницу через `ContentTemplate` и сохраняет её для следующих переходов. Onboarding больше не требует создания MainPage, AddConsumptionPage и CalendarPage до первого показа.
- После загрузки Shell в фоновом потоке прогревается только кеш статистики календаря. Создание скрытой CalendarPage и отложенное обновление её привязок через 500 мс удалены.
- MainPage публикует первоначальную историю одним изменением `ItemsSource`, вместо отдельных уведомлений для каждой записи. Добавление и удаление записей по-прежнему обновляют коллекцию и статистику.
- На Android системные панели, вырезы и клавиатуру учитывает один `WindowInsetsCompat` listener на постоянном контейнере Activity. Он обновляет padding только при изменении отступов и поглощает insets до их передачи страницам. Android-страницы, включая onboarding, используют `SafeAreaEdges=None`; на остальных платформах остаётся `All`. Промежуточная проверка показала, что одной унификации XAML недостаточно: новый Shell fragment ещё мог показать кадр до получения отступов.
- Вложенные Grid не добавляют собственные системные отступы. У основных трёх экранов одинаковые строки заголовка (86 DIP) и нижней навигации (88 DIP).
- Исправлен `Grid.Row=1` у кнопок панели, где существует только строка 0.
- Все программные переходы остаются в `AppNavigationService`: общий semaphore, выполнение на UI-потоке, переходы без анимации, пропуск повторного текущего маршрута. При выходе из настроек через нижнюю панель сначала выбирается целевая вкладка, затем закрывается модальное окно.

Сохранены Shell-маршруты, стек Settings → PrivacyPolicy, состояние формы, обработка событий данных и таймеры видимых страниц. Настройки и политика остаются transient: их XAML создаётся с актуальным языком.

## Проверка на устройстве

Выполнено 08.09.2026 на Samsung Galaxy A52 (SM-A525F), Android 14, в отдельном Release-приложении `com.companyname.coffeenap.performancecheck`, без изменения данных основного приложения:

- Android Debug (финальная компиляция) и Release (полная сборка с AOT): 0 ошибок, 0 предупреждений.
- Onboarding, повторный запуск с профилем, все пять экранов, системная Back и кнопки возврата, выход из Settings на другую вкладку.
- Состояние результата формы после перехода Main → Add; сохранение энергетика 250 мл, появление 80 мг в истории, дневном итоге и календаре.
- Открытие/закрытие клавиатуры: поле имени и Confirm остаются в доступной области; подтверждение переводит на Main.
- В промежуточной версии пойман кадр со смещённым заголовком Add. После общего Android inset listener смещение в повторном захвате не воспроизвелось: область заголовка `(0,88)-(1080,314)` идентична пиксель в пиксель на 21 снимке переходов Calendar → Add → Main. Это выборочная проверка кадров через ADB, не высокочастотный frame trace и не замер времени навигации.

Материалы локальной проверки находятся в игнорируемом git каталоге `artifacts/android-performance/`; итоговая серия — `fixed/transitions.png`. Сравнение скорости с исходным commit не проводилось, процент ускорения не заявляется. Android 15/16, другие устройства, ориентации и масштабы шрифта остаются для дополнительной проверки.

### Повторная проверка

Проверять Release без подключённого отладчика. Не сравнивать время первого запуска после установки с обычным повторным запуском процесса.

1. Пройти onboarding; закрыть и заново открыть приложение с сохранённым профилем.
2. Первый и повторные переходы Main → Calendar → Add → Main; быстрые последовательные нажатия.
3. Открыть настройки и политику, вернуться кнопкой приложения и системной Back; выйти из настроек на другую вкладку.
4. Пройти ветви кофе/чая/энергетика, сохранить запись, проверить историю и календарь; удалить тестовую запись.
5. Повторить с открытой клавиатурой, в альбомной ориентации, с жестовой и трёхкнопочной системной навигацией. Проверить также Android 15/16 (edge-to-edge) и увеличенный шрифт.

Для оценки подёргивания нужна запись кадров перехода, а для времени загрузки — одинаковые устройство, данные, конфигурация и серия холодных/повторных переходов. Успешная компиляция сама по себе не подтверждает отсутствие пропущенных кадров.
